# Автозапятые

Фоновая помощь с русскими запятыми для Windows 10/11 x64. Точки вы ставите самостоятельно.
Приложение использует готовые локальные правила LanguageTool, без LLM, нейросетей, аккаунта и облачных запросов.

**Первая версия экспериментальная.** Автоматические тесты и сборка проверяют свой контракт;
совместимость с конкретным редактором требует проверки в его настоящем поле ввода.
Сборка установщика не означает, что все приложения Windows поддерживаются.

## Установка

1. Скачайте `AutoPunct-0.1.0-Setup.exe` из релиза или артефакта сборки Windows.
2. Запустите установщик. Для регистрации модуля ввода нужны права администратора.
3. Запустите «Автозапятые» из меню «Пуск».
4. В параметрах языков Windows выберите русский метод ввода **«Автозапятые»**.
   Если профиль ещё не появился, выйдите из учётной записи Windows и войдите снова.
5. Откройте поле ввода и напишите `Известно что на улице красивый вид `, включая пробел в конце.
   После короткой паузы должна появиться запятая: `Известно, что …`.

Java входит в установщик: отдельно устанавливать её не требуется.
Настройки раскладки по умолчанию установщик не меняет. Автозапуск изначально выключен.

## Управление

- Иконка с запятой находится в трее. Меню позволяет поставить помощь на паузу и продолжить её.
- Перед открытием меню выберите приложение, которое хотите исключить. Исключение можно снять в том же меню.
- «Автозапуск» включает запуск только для текущего пользователя и только для установленной версии.
- `Ctrl+Alt+Backspace` отменяет последнюю автоправку, пока соответствующий текст и поле не изменились.
- «Выход» завершает Java-приложение. При выключенном приложении обычный ввод продолжает работать.

## Как выбираются правки

Проверка запускается после 600 мс без изменения поля, когда слово завершено пробелом или знаком пунктуации.
Размер анализируемого фрагмента — не более 512 символов UTF-16. Неоднозначные предложения пропускаются.
Первая версия включает шесть готовых правил LanguageTool:
`CHTO_COMMA`, `A_NO_DA`, `PUNKT_KOTORIJ`, `PUNKT_KOTORIJ1`, `comma_and_to_jest`, `PUNCT_VB_INF_OBOROT`.

Принимаются только вставки запятых. Буквы, пробелы, точки и остальные уже набранные знаки сохраняются.
Снимок текста повторно проверяется перед вставкой. Текст меняется через сеанс редактирования Windows TSF.
Приложение не читает и не заменяет буфер обмена.

Парольные поля, консоли, поля с неизвестными свойствами доступа и незавершённые составные вводы пропускаются.
По умолчанию исключены терминалы, PowerShell, Visual Studio Code, Visual Studio, IntelliJ IDEA, PyCharm и Notepad++.
Существующие запятые не удаляются. Сплошной текст без пробелов, длинные предложения и неподдерживаемые поля не исправляются.

Набранный текст хранится только временно в памяти для проверки и отмены; история и текстовые журналы не создаются.
Сохраняются только пауза и список исключённых приложений текущего пользователя.

## Архитектура

Java 17, Spring Boot 4.1.1, DDD и CQRS. Диспетчеризация выполняется готовой библиотекой PipelinR 0.11,
которая также лежит в основе `java-message-bus`. Контексты разделены по смыслу, слои находятся внутри них.

- `typing/assistance`: корень `Profile` владеет паузой и исключениями; команды изменяют только его.
  `ProfileRepository` сохраняет весь корень посредством стандартного отображения Jackson.
  Доменные события публикуются через Spring после сохранения.
- `typing/commas`: запрос проверки, обработчик, адаптер LanguageTool и чистое правило допустимых вставок.
  Запрос не меняет документ Windows и не сохраняет введённый текст.
- `windows`: доступ к сеансу Windows и команды регистрации автозапуска.
- `native`: небольшой модуль C++ на LibIME2, отвечающий за TSF, актуальность снимков и применение правок.

Команды и запросы лежат рядом со своими обработчиками. Трей и входящий локальный канал отправляют сообщения через
PipelinR. Spring Boot запускается без HTTP-сервера. Kafka, база данных и внешние службы для работы не нужны.

## Проверки и сборка

Для переносимой Java-части и проверок C++:

```sh
docker compose build builder
docker compose up -d --no-build builder
docker compose exec -T builder mvn -B -ntp verify
docker compose exec -T builder cmake -S native -B build/native-linux
docker compose exec -T builder cmake --build build/native-linux --parallel 2
docker compose exec -T builder ctest --test-dir build/native-linux --output-on-failure
```

Maven-кэш находится в соседнем рабочем каталоге `work/autopunct/maven-cache` для этого checkout.
Путь можно заменить своим каталогом кэша в локальном файле Compose.

Для установщика нужны Windows, JDK 17, Maven, Visual Studio 2022 с C++, Windows SDK, CMake и Inno Setup 6:

```powershell
./packaging/Build-Windows.ps1
```

Та же процедура включена в GitHub Actions. Она проверяет Java, собирает модули x86/x64, проверяет их экспорт
и готовит установщик со встроенной Java. Версии Java-библиотек указаны в `pom.xml`, LibIME2 закреплена по коммиту.
Исходники и команды сборки доступны для повторной сборки и перелинковки с изменённой LibIME2.

Сведения о совместимости, обязательные ручные сценарии и результаты замеров: [Проверка Windows](docs/windows-validation.md).
Сторонние лицензии: [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

## Готовые решения, рассмотренные перед разработкой

- [LanguageTool](https://dev.languagetool.org/http-server): автономная проверка без облачных AI-правил; выбран как основа.
- [Eloquent](https://github.com/sonnyp/Eloquent): готовый автономный интерфейс для Linux.
- [Espanso](https://espanso.org/): замена заданных текстовых шаблонов; не восстанавливает пунктуацию по контексту.
- [LibIME2](https://github.com/EasyIME/libIME2): готовая основа службы ввода Windows; выбран вместо собственной реализации COM/TSF.
